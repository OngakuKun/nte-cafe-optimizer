What it does

Everything in one place

A small C core, a friendly interface, and the same config whether you run it in a browser, on your desktop or from the command line.

Real optimization

Scores every valid dish and character combination for your settings and returns the best result with income, traffic and buffs.

Your roster, your rules

Mark characters and dishes as owned, set their levels, adjust cafés, trend and decor. The result updates to match.

One config everywhere

WebUI, desktop app and CLI share one ID-keyed config.json. Export it, import it, or just copy it to another machine.

Desktop or browser

The native desktop build uses the same UI and bindings. No WebView runtime? It opens in your default browser instead.

Make it yours

Catppuccin themes, theme import, and English/German interface text. Game data stays the source of truth.

Easy to run

One Docker Compose command, or a plain CMake build. No services to register for and no secrets to configure.

How it works

Four steps to a better loadout

From an empty setup to a concrete recommendation — no spreadsheet required.

  1. 01

    Set the frame

    Choose how many cafés you own, the active trend and whether Hotori's Cat Decor is on.

  2. 02

    Mark your roster

    Flag owned characters (level 1 or higher counts) and owned dishes on the card pages.

  3. 03

    Run the optimizer

    The C core checks the combinations and presents the top result with all bonuses included.

  4. 04

    Save or share

    Export your config from Settings, import it elsewhere, or keep using the same desktop binary.

Get started

Run it your way

Clone with submodules first: git clone --recurse-submodules. Then pick one of these.

With Docker

docker compose up -d --build
# UI at http://localhost:18423

Compose persists the shared config in a named volume, so your roster survives rebuilds.

From source

./build.sh Debug
./build/app/nte-cafe-app
# desktop: cmake --build build --target nte-cafe-desktop

Open the UI through the app server — the page bindings need the backend, not just the HTML files.

Full requirements, environment variables and deployment notes are in the README ↗.
